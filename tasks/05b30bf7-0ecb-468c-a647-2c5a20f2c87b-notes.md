# Authenticated image upload + Buffer publishing

## Goal
Receive a generated image as binary data, commit it to this repository, and publish it with a caption through Buffer to the Share2Me LinkedIn channel.

## Current implementation
- Added a manual GitHub Actions workflow at .github/workflows/publish-linkedin-post.yml.
- Workflow inputs: an existing image path under images/, a caption path under captions/, and whether to publish immediately or queue.
- Workflow calls Buffer's GraphQL API with an image asset URL derived from the raw GitHub URL.
- The workflow requires repository secrets BUFFER_API_KEY and BUFFER_CHANNEL_ID.
- The Share2Me LinkedIn channel ID currently configured in Buffer is 6ad0d64b778b240e2f18c514.

## Still required
- Binary upload from the ChatGPT-generated PNG into images/.
- Add repository secret BUFFER_API_KEY using the correct Buffer API key (do not use a token for a different API).
- Add repository secret BUFFER_CHANNEL_ID with value 6ad0d64b778b240e2f18c514.
- Test the workflow with the real generated image and verify Buffer's returned post includes an image asset and status sent.

## Known connector limitation
The GitHub connector available here can commit text files but does not expose a supported operation for transferring PNG bytes. It can't upload the image just by virtue of repository write permissions. The authenticated upload endpoint still needs to be implemented and deployed to receive actual image bytes, or a binary-capable upload integration must be added.

## Security
- Never commit secrets.
- The upload endpoint must authenticate requests, validate file signature and MIME type, enforce a body size cap, allow safe filenames, avoid logging secrets, and return the public raw URL only after upload succeeds.
- Avoid duplicate posts on retries by using an idempotency key.
